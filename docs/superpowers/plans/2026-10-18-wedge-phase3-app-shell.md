# Wedge Phase 3 (Menu-bar app shell) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax. NOTE: every task needs **full Xcode** (xcodebuild) + **xcodegen**; do not start execution until Xcode is installed and `xcode-select -p` points at Xcode.app.

**Goal:** A menu-bar macOS app (`Wedge.app`) that imports files by drag-drop, converts them via `WedgeCore` with progress, and offers settings incl. launch-at-login — no radial wheel yet (that is Phase 4).

**Architecture:** SwiftUI `App` with `MenuBarExtra`; a testable `@MainActor @Observable ConversionModel` wraps `ConversionService`; a floating shelf window for drag-drop + convert; a settings window with a mockable `LoginItemService` over `SMAppService`. Project generated by xcodegen; app depends on the local `WedgeCore` SwiftPM package.

**Tech Stack:** Swift 6, SwiftUI + AppKit, xcodegen + xcodebuild (Xcode 16+), WedgeCore (local package), Swift Testing.

**Spec:** docs/superpowers/specs/2026-10-18-wedge-gui-design.md

## Global Constraints
- macOS 13+, Swift 6 strict concurrency. App is `LSUIElement` (menu-bar only, no Dock icon).
- `WedgeCore` stays UI-agnostic; no conversion logic in the app target. Reuse `Wedge.defaultRegistry()` / `ConversionService`.
- Clean-room (no "Tangerine"); product "Wedge"; no AI-assistant/vendor names in code or commit messages (clean-room name check empty before each commit).
- Never overwrite silently (the model surfaces OutputNamer behavior; honor `force` only on explicit user action).
- Offline. No new runtime network calls.
- Project is xcodegen-generated: commit `project.yml`, NOT a hand-edited `.xcodeproj` (add `*.xcodeproj` to .gitignore). CI runs `xcodegen generate` then `xcodebuild`.
- Logic lives in testable view-models/services; UI views kept thin. Build/verify each task with `xcodebuild -scheme Wedge build` and `./scripts/test.sh` (core tests) + the app target's unit tests.

## Review Focus
- **Drop of an unsupported file type** → shelf shows it as unconvertible / offers only valid targets, never silently no-ops; pinned in Task 3.
- **Convert while a job is running / cancel mid-batch** → model state stays consistent (no double-run, cancel leaves partials handled); pinned in Task 2.
- **Launch-at-login toggle fails** (SMAppService error) → surfaced to the user, state reflects reality; pinned in Task 4.
- **Output collision from the UI** → non-destructive default; overwrite only on explicit choice; pinned in Task 2/3.
- **App with no accessibility/again-launch** → menu-bar item always reachable; second launch focuses existing instance; pinned in Task 5.
